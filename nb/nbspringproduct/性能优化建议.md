# 农宝系统性能优化建议

## 📊 问题分析

### 1. 重复查询问题
从日志中发现，同一个查询在短时间内被执行了多次：

```sql
SELECT id,title,resume,description,image,catgory,produce_type,price,browse_num,push_status,push_time,recommend,provider_name,account_id,created_time,updated_time,create_by,create_time,update_by,update_time,remark 
FROM nb_farm_produce 
ORDER BY create_time DESC
```

**影响：**
- 浪费数据库连接资源
- 增加网络传输开销
- 每次都查询 BLOB 字段（resume、description、image），数据量大

---

## ✅ 已实施的优化

### 1. 前端防重复请求
在 `ProduceManagement.vue` 中添加了请求锁：

```typescript
let fetchingData = false // 防止重复请求

const fetchList = async () => {
  if (fetchingData) {
    console.log('⚠️ 请求正在进行中，跳过重复请求')
    return
  }
  fetchingData = true
  // ... 请求逻辑
  fetchingData = false
}
```

### 2. 本地数据更新
推荐/取消推荐操作改为本地更新，避免重新请求：

```typescript
// 本地更新数据，避免重新请求
row.recommend = row.recommend === 1 ? 0 : 1
applyFilters()
```

#### 1.2 分离大字段查询
创建两个查询方法：

**列表查询（不含大字段）：**
```java
@Override
public List<NbFarmProduce> selectFarmProduceListSimple(NbFarmProduce produce) {
    LambdaQueryWrapper<NbFarmProduce> wrapper = new LambdaQueryWrapper<>();
    
    // 只查询列表需要的字段，排除 description、image 等大字段
    wrapper.select(
        NbFarmProduce::getId,
        NbFarmProduce::getTitle,
        NbFarmProduce::getResume,
        NbFarmProduce::getCatgory,
        NbFarmProduce::getProduceType,
        NbFarmProduce::getPrice,
        NbFarmProduce::getBrowseNum,
        NbFarmProduce::getPushStatus,
        NbFarmProduce::getPushTime,
        NbFarmProduce::getRecommend,
        NbFarmProduce::getProviderName,
        NbFarmProduce::getCreateTime
    );
    
    // 条件和排序
    wrapper.like(StringUtils.isNotBlank(produce.getTitle()), NbFarmProduce::getTitle, produce.getTitle());
    wrapper.eq(StringUtils.isNotBlank(produce.getCatgory()), NbFarmProduce::getCatgory, produce.getCatgory());
    wrapper.eq(produce.getPushStatus() != null, NbFarmProduce::getPushStatus, produce.getPushStatus());
    wrapper.eq(produce.getRecommend() != null, NbFarmProduce::getRecommend, produce.getRecommend());
    wrapper.orderByDesc(NbFarmProduce::getCreateTime);
    
    return this.list(wrapper);
}
```

**详情查询（含所有字段）：**

```java
@Override
```

#### 2.2 添加缓存
使用 Redis 缓存列表数据：

```java
@Service
public class NbFarmProduceServiceImpl extends ServiceImpl<NbFarmProduceMapper, NbFarmProduce> 
        implements INbFarmProduceService {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    private static final String CACHE_KEY = "farm_produce_list";
    private static final long CACHE_TIMEOUT = 5 * 60; // 5分钟
    
    @Override
    public List<NbFarmProduce> selectFarmProduceList(NbFarmProduce produce) {
        // 尝试从缓存获取
        String cacheKey = CACHE_KEY + ":" + buildCacheKey(produce);
        Object cached = redisTemplate.opsForValue().get(cacheKey);
        
        if (cached != null) {
            return (List<NbFarmProduce>) cached;
        }
        
        // 查询数据库
        LambdaQueryWrapper<NbFarmProduce> wrapper = new LambdaQueryWrapper<>();
        // ... 查询逻辑
        List<NbFarmProduce> list = this.list(wrapper);
        
        // 存入缓存
        redisTemplate.opsForValue().set(cacheKey, list, CACHE_TIMEOUT, TimeUnit.SECONDS);
        
        return list;
    }
    
    // 更新/删除时清除缓存
    @Override
    public int updateFarmProduce(NbFarmProduce produce) {
        int result = this.updateById(produce) ? 1 : 0;
        if (result > 0) {
            clearCache();
        }
        return result;
    }
    
    private void clearCache() {
        Set<String> keys = redisTemplate.keys(CACHE_KEY + ":*");
        if (keys != null && !keys.isEmpty()) {
            redisTemplate.delete(keys);
        }
    }
}
```

### 4. 数据库连接池优化

在 `application.yml` 中优化 HikariCP 配置：

```yaml
spring:
  datasource:
    hikari:
      # 最小空闲连接数
      minimum-idle: 5
      # 最大连接池大小
      maximum-pool-size: 20
      # 连接超时时间（毫秒）
      connection-timeout: 30000
      # 空闲连接最大存活时间（毫秒）
      idle-timeout: 600000
      # 连接最大生命周期（毫秒）
      max-lifetime: 1800000
      # 连接测试查询
      connection-test-query: SELECT 1
```

```java
@Aspect
@Component
public class PerformanceAspect {
    
    @Around("execution(* com.movie.nbspringproduct.service..*.*(..))")
    public Object logPerformance(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = joinPoint.proceed();
        long end = System.currentTimeMillis();
        
        String methodName = joinPoint.getSignature().getName();
        long duration = end - start;
        
        if (duration > 1000) { // 超过1秒的慢查询
            System.out.println("⚠️ 慢查询警告: " + methodName + " 耗时 " + duration + "ms");
        }
        
        return result;
    }
}
```

## 🔍 问题排查

如果仍然出现重复查询，请检查：

1. **前端是否有多个组件同时调用接口**
   - 检查 `onMounted`、`watch`、`computed` 等钩子
   - 使用浏览器开发者工具的 Network 面板查看请求

2. **路由守卫是否重复触发**
   - 检查 `router.beforeEach` 等导航守卫

3. **是否有定时器自动刷新**
   - 检查 `setInterval`、`setTimeout` 等

4. **父子组件通信问题**
   - 检查 `props`、`emit` 是否导致重复渲染
