# 性能优化执行指南

## 📋 优化内容概述

本次优化主要解决了 **重复查询** 和 **查询性能** 问题。

### 问题现象
从日志中发现，同一个查询在短时间内被执行了多次：
```
==> Preparing: SELECT * FROM nb_farm_produce ORDER BY create_time DESC
<== Total: 15
```
这个查询重复执行了 4 次，导致性能浪费。

---

## ✅ 已完成的优化

### 1. 前端防重复请求
**文件：** `nbvueproject/src/components/views/ProduceManagement.vue`

**改动：**
- 添加了 `fetchingData` 标志防止重复请求
- 推荐/取消推荐操作改为本地更新，避免重新请求
- 添加了请求日志，方便调试

**效果：**
- ✅ 防止同一时间发起多个相同请求
- ✅ 减少不必要的数据库查询
- ✅ 提升用户操作响应速度

## ❓ 常见问题

### Q1: 索引创建失败怎么办？
**A:** 可能是索引已存在，可以先删除再创建：
```sql
-- 删除索引
ALTER TABLE nb_farm_produce DROP INDEX idx_create_time;

-- 重新创建
ALTER TABLE nb_farm_produce ADD INDEX idx_create_time (create_time DESC);
```

### Q2: 优化后还是有重复查询？
**A:** 请检查：
1. 前端代码是否已更新（检查 `ProduceManagement.vue` 中的 `fetchingData` 变量）
2. 浏览器缓存是否清除（Ctrl + Shift + R 强制刷新）
3. 是否有多个页面同时打开

### Q3: 如何回滚优化？
**A:** 删除索引即可：
```sql
-- 删除所有新增的索引
ALTER TABLE nb_farm_produce DROP INDEX idx_create_time;
ALTER TABLE nb_farm_produce DROP INDEX idx_push_status;
ALTER TABLE nb_farm_produce DROP INDEX idx_recommend;
-- ... 其他索引
```

前端代码可以使用 Git 回滚：
```bash
git checkout HEAD -- nbvueproject/src/components/views/ProduceManagement.vue
```
